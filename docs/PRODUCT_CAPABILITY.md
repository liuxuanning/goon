# Goon 产品机会筛选器：能力定义

## CAPABILITY
将多来源公开新品记录转化为可追溯、可复核的产品机会候选。系统帮助两人 OPC 团队发现值得进一步研究的用户问题，而不是仅按新品榜单热度推荐创业方向。

## 固定约束与不变量
1. 原始来源事实、系统计算、AI 推断、人工判断、未知字段必须分层存储和展示。
2. 榜单位置只在同一来源、同一榜单定义、同一国家/地区、同一平台和可比时间范围内解释；Apple 新应用 Feed 位置永远不得称为市场排名。
3. 缺失值必须保持 null/未知，不得用 0、默认值、示例值或推算值冒充事实。
4. 每条证据保留来源 URL、采集时间、原始内容/快照、字段来源及校验状态。
5. 趋势判断必须有足够历史快照；不同来源的名次不可直接横向比较。
6. AI 输出是待复核假设，不得自动升级为已验证需求或机会结论。
7. 所有 AI 结论需保留输入快照、输入哈希、模型、提示词版本、输出、证据定位、校验结果和人工复核记录。
8. 两人协作的候选、标签、复核与决策必须服务端持久化并记录操作者和时间。

## 用户与界面
- 研究员：采集、补全、聚类、提交候选和证据。
- 复核者：独立检查来源、用户痛点、竞品、付费证据和不确定性。
- 管理者/创始人：查看机会排序、证据缺口和验证结论。

## 核心生命周期
发现 → 数据质量检查 → 历史趋势观察 → 需求假设聚类 → 多维证据补齐 → 候选提交 → 双人复核 → 小规模验证 → 通过/观察/否决。

## 机会证据维度
- 需求证据：真实评论、社区讨论、搜索趋势、用户任务和痛点原文。
- 趋势证据：来源可比的排名轨迹、榜单重复出现、评分/评论量变化。
- 商业证据：价格、订阅/一次性付费、竞品收入公开线索、用户付费表达。
- 竞争证据：直接竞品、替代方案、差评缺口、产品差异化。
- OPC 可行性：两人可交付范围、获客渠道、成本/依赖、合规和维护负担。

## 非目标
- 不把新品榜单当作市场规模或收入数据。
- 不把 AI 置信度当作统计置信区间。
- 不自动发布内容、购买流量或对外联系用户。
- 不在没有证据时生成机会分数或成功概率。

## 关键状态
`raw`、`quality_checked`、`observing`、`clustered_unreviewed`、`evidence_pending`、`submitted`、`in_review`、`validated`、`watchlist`、`rejected`。

## 开放决策
- 生产部署是否已有反向代理/API 鉴权，需核验后再开放协作接口。
- 豆包 API 的具体模型、账号配额和数据保留策略需由部署配置确认。
- 评论/社区数据采集需逐来源核对平台条款和速率限制。
- 双人账号身份方案（内置账号或企业身份提供方）需确定。

## 交付顺序
P0 数据可信度与演示数据隔离；P1 数据字段/来源契约和质量报告；P2 趋势快照与可比性；P3 可审计豆包需求聚类；P4 多维证据与双人复核；P5 自动化部署、备份、监控与回滚。
